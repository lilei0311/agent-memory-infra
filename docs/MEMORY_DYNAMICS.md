# Memory Dynamics: Event Blocks, Threads, and Human-Inspired Lifecycle\n\n## Status\nResearch design. This document defines the new lower-level research direction after the V0.1 robustness experiments. It is intentionally separate from the existing V0.1 retrieval implementation.\n\n> A memory is not a static record. It is a dynamic trace formed from events, connected across time, strengthened or weakened by later experience, reactivated by retrieval, updated through reconsolidation, and eventually made less accessible or forgotten.\n\n## 1. Two applications, one lower layer\nThe same memory-dynamics layer should support two later directions:\n\n- Agent Memory: help an Agent manage experience, feedback, outcomes, contradiction, context and reactivation.\n- Human Memory Assistance: use the same model to decide what a learner should recall, when to review it, how to test it, and when to reinforce or revise it.\n\nThese applications are intentionally above the lower-level research model.\n\n## 2. Core primitive: Event Instance\nA memory should not begin as a detached fact. The minimum primitive is an Event Instance: one observed episode in which something happened and produced a response, feedback or outcome.\n\nConceptually:\n\nContext + Participants + Goal + Action/Observation + Feedback/Response + Outcome/State Change = Event Instance\n\nMinimum fields:\n\n| Field | Meaning |\n|---|---|\n| event_id | Unique occurrence identity |\n| timestamp | When it occurred |\n| participants | Who or what participated |\n| context | Situation in which it occurred |\n| goal | Intended objective, when known |\n| action | What was done or what happened |\n| feedback | Immediate response from environment, user or another participant |\n| outcome | Result or state change, when known |\n| evidence | Evidence supporting the observation |\n| source | Origin of the observation |\n| parent_thread | Event thread(s) to which it belongs |\n| relations | Links to other events |\n\nStrength, confidence, decay and retrieval priority are not intrinsic event content. They are dynamic state derived from the event history.\n\n## 3. Action and feedback form one experiential unit\nFor both humans and Agents, the useful learning signal is often the relationship between action and consequence, not either item alone.\n\nAgent: action → environment/user response → outcome → experience\n\nHuman: action/observation → other person/environment response → emotional/practical outcome → experience\n\nTherefore an event should preserve the action → feedback → outcome relationship.\n\n## 4. Event Thread: repeated occurrences are linked, not merged\nThe same subject may recur today, two days later, or two weeks later. Each occurrence remains a separate Event Instance, but related occurrences belong to an Event Thread.\n\nExample:\n\nEvent 001 → Event Thread: economics-exam\nEvent 002 → Event Thread: economics-exam\nEvent 003 → Event Thread: economics-exam\n\nDo not overwrite repeated events into one mutable record. Preserve temporal evidence and link the occurrences.\n\n## 5. Relations\nInitial relation types:\n\n- Temporal: before, after, overlaps, recurring\n- Causal: caused_by, caused, enabled, prevented\n- Referential: refers_to, same_thread, revisits\n- Evidential: confirms, contradicts, weakens, strengthens\n- Contextual: same_context, changed_context, related_context\n\nSemantic similarity alone is not enough to represent these relationships.\n\n## 6. Memory as dynamic state over event history\nConceptually:\n\nMemory = Event History + Relations + Current Dynamic State\n\nThe dynamic state should eventually distinguish at least:\n\n- accessibility\n- current confidence\n- evidence/history\n- contextual fit\n- recency\n- reinforcement history\n- contradiction history\n\nDo not collapse these into one scalar too early. A future retrieval score may derive from them, but the underlying state should remain inspectable.\n\n## 7. Human-inspired state machine\nThe first research state machine is:\n\nFORMING\n  ↓ encoding succeeds\nLABILE / NEW\n  ↓ consolidation\nSTABLE\n  ├─ retrieval → REACTIVATED → RECONSOLIDATING\n  ├─ low use / time → DORMANT\n  └─ contradiction → WEAKENED\n\nRECONSOLIDATING\n  ├─ confirmation → STABLE\n  ├─ revision → UPDATED → STABLE\n  └─ contradiction → WEAKENED\n\nDORMANT\n  └─ useful cue/retrieval → REACTIVATED\n\nWEAKENED\n  ├─ new evidence → RECONSOLIDATING\n  └─ prolonged low accessibility → FORGOTTEN / INACCESSIBLE\n\nThis is a computational research model, not a claim that the brain literally has these software states.\n\n## 8. Existence, accessibility, trust and usefulness are different\nA memory existing is not the same as being accessible, trustworthy or useful.\n\nAsk four separate questions:\n\n1. Is there evidence that this experience occurred?\n2. Can the system currently retrieve it?\n3. How strongly should it believe that the experience applies now?\n4. Is it useful for the current task?\n\nThis distinction is central to both Agent Memory and human memory assistance.\n\n## 9. Positive and negative experience\nMemory should not strengthen only after success. A strong negative outcome can also produce a strong trace.\n\nThe eventual model should distinguish the sign of an outcome from its learning impact. Candidate signals include positive/negative outcome, feedback intensity, surprise or prediction error, repetition, later confirmation and later contradiction.\n\nExample hypothesis:\n\nweak success → small reinforcement\nstrong success → strong reinforcement\nweak failure → small correction\nsevere failure → strong correction\n\nThis is a research hypothesis, not yet a hard-coded rule.\n\n## 10. Retrieval is an event\nRetrieval should itself enter the event history:\n\nmemory retrieved → memory reactivated → new experience → confirmation/contradiction/modification → state update\n\nThis is the computational analogue of reactivation and reconsolidation.\n\nTherefore a retrieval record should distinguish retrieved, actually used, successful, contradicted, revised and ignored.\n\nA retrieval that was never used should not automatically count as successful reinforcement.\n\n## 11. Forgetting is not necessarily deletion\nThe original project began with an Ebbinghaus-style forgetting curve. That remains useful, but only as one mechanism.\n\nAccessibility can decline because of time, lack of retrieval, competing memories, context change, contradiction or reduced usefulness.\n\nAccessibility can recover because of retrieval, successful use, related events, context reactivation or reconfirming evidence.\n\nTherefore the target is not simply strength(t) = strength0 × decay(t). The broader hypothesis is:\n\ncurrent memory state = historical experience + temporal effects + retrieval history + evidence + context + reconsolidation\n\nThe mathematical form remains deliberately open until the biological literature review is complete.\n\n## 12. From events to higher-level knowledge\nRepeated events can produce an abstraction, but the abstraction should not replace the evidence.\n\nExample:\n\nrepeated economics mistakes + corrections + later successful recall\n→ pattern: learner understands the definition but confuses two related concepts\n\nKeep both:\n\n1. episodic evidence: what actually happened;\n2. abstracted knowledge: the pattern inferred from multiple events.\n\nAn abstraction should retain links to the events that produced it.\n\n## 13. Relationship to V0.1\nV0.1 currently models a much smaller object: MemoryItem → success/failure counts → utility → adaptive retrieval score.\n\nPhase D/E showed that accumulated utility becomes stale when the environment changes. The new model explains the structural limitation: V0.1 treats experience mainly as an accumulated score rather than temporal, contextual and relational event history.\n\nTherefore V0.2 should not simply add more weights to the old score. It should first establish the event/thread/state model.\n\n## 14. Research layers\nLayer 1 — Event representation: Event Instance, Event Thread, Event Relations.\nLayer 2 — Memory state machine: forming, consolidation, stable, retrieval/reactivation, reconsolidation, weakened/dormant, reactivation and inaccessible/forgotten.\nLayer 3 — Dynamics: reinforcement, decay, contradiction, context shift, reactivation, exploration and re-evaluation.\nLayer 4 — Policy: write, retrieve, retain, forget, abstract.\nLayer 5 — Applications: Agent Memory and Human Memory Assistance.\n\n## 15. Human Memory Assistance hypothesis\nA future learning Agent should not behave as User asks → answer → done.\n\nIt should behave more like:\n\nlearn → initial encoding → wait → active recall → feedback → re-explanation if needed → successful retrieval → spaced reactivation → context variation → long-term stabilization\n\nFor an economics-exam learner, the Agent could decide when to test a weak concept, increase intervals after successful recall, create contrast questions for recurring confusions, and test transfer in a new context.\n\nThis is a later application, not part of the V0.1 implementation.\n\n## 16. Research principles\n1. Do not overfit to Ebbinghaus; forgetting is one mechanism.\n2. Do not collapse memory into one scalar too early.\n3. Preserve individual events.\n4. Preserve causal structure where evidence supports it.\n5. Treat retrieval as an interaction that can change future state.\n6. Separate evidence from inference.\n7. Do not confuse forgetting with deletion.\n8. Preserve agent-agnostic and storage-agnostic architecture.\n9. Biological inspiration is a design hypothesis, not a claim of biological equivalence.\n10. New mechanisms must be isolated in controlled experiments without post-hoc tuning.\n\n## 17. Immediate research questions\n1. What does biological research say about event segmentation and event boundaries?\n2. What evidence supports linking repeated events into episodic threads?\n3. How are action, outcome, emotional salience and prediction error related to consolidation?\n4. What distinguishes retrieval failure from loss of an underlying memory trace?\n5. What changes during reconsolidation?\n6. How should competing or contradictory memories coexist?\n7. Which variables can be measured reliably enough for a computational model?\n8. Which mechanisms are necessary for the smallest useful Agent implementation?\n9. Which mechanisms can support a human-learning application without unsupported neuroscience claims?\n\nOnly after these questions are answered should the V0.2 transition equations and implementation API be frozen.
